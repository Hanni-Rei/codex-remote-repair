# Codex Remote 修复方案

Windows 桌面版 Codex Remote 的故障分类、证据排查、针对性修复与实际验收记录。

**先确认故障类型，再选择修复方法。** “无法更新远程控制状态”只是界面提示，不能单凭它判定重复实例、网络或账号问题。

## 按症状选择方案

| 症状与现场证据 | 处理方向 | 详细指南 |
|---|---|---|
| 手机提示“已在另一个应用中打开”；同一桌面主应用下确有重复 `app-server`，日志支持异常重建后残留 | 保存工作，完整退出并只启动一次 Codex | [重复后端单实例冲突](Codex-Remote修复方法-重复后端冲突-20260915.md) |
| “无法更新远程控制状态”；远程控制 WebSocket 报 `os error 10060`；直连超时而现有代理可达 | 检查远程连接的代理路径；需要 TUN 时核对管理员或服务权限 | [网络超时与 TUN 权限](Codex-Remote修复方法-网络超时与TUN权限-20261011.md) |
| 后端正常且网络可达，但仍无法连接 | 检查账号、工作区、设备授权、主机睡眠及当前错误 | 本仓库暂无已验收的专门方案 |
| 远程可用，但手机与电脑的对话列表不同步 | 检查任务归档、筛选、索引与账号工作区 | 本仓库暂无已验收的专门方案 |

## 推荐排查顺序

1. 记录提示原文、发生时间、当前版本和正在运行的任务。
2. 核对桌面主应用与后端的父子关系、完整命令行和启动时间。多个渲染器、工具进程或独立 CLI 不等于重复后端。
3. 结合故障时段日志，区分本地初始化、远程网络连接、账号配对及界面状态问题。
4. 保存基线，只修改证据指向的部分；重启应用或代理前确认任务中断范围。
5. 验证后端、远程状态和设备列表，再在手机上连接并实际操作已有对话。

## 使用边界

- 本仓库是排查与修复案例，不是 OpenAI 官方修复工具，不保证覆盖所有版本或故障。
- 进程编号、安装路径、日志位置和接口可能变化，使用前必须现场核对。
- TUN 会改变网络路由。仅在证据支持、且操作范围明确时使用；保留现有节点与规则，修改前备份。
- `HTTP 426` 只说明测试请求收到了服务端响应，不能替代带身份认证的 WebSocket 连接和手机实测。
- “命令成功”“窗口打开”或“开关开启”不能代替实际验收；缺失验证时明确标注“待验证”。

公开问题或贡献记录时，请先去除令牌、账号与设备标识、私人路径、订阅地址和其他敏感信息。
